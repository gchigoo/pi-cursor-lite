# Iteration 005

## Current Understanding

owner 明确拒绝等待上游和接受已知漏洞，要求在本项目内直接修复。根级 `overrides` 与发布包内 `npm-shrinkwrap.json` 均不能向普通 npm 消费者传递安全版本；主包必须提供一个满足 Cursor SDK `@connectrpc/connect-node@^1.6.1` 的安全依赖节点。

## Implementation Approach

采用项目内维护的 Apache-2.0 Connect Node 兼容 fork，而不是重发专有许可的 Cursor SDK：

- 以 upstream `@connectrpc/connect-node@1.7.0` 的发布产物为基线。
- 下游包名和版本为 `@gchigoo/connect-node@1.7.1`。
- 运行时代码和类型声明保持逐字节一致，只将 `undici` 从 `^5.28.4` 改为固定 `6.27.0`。
- 后续主包使用 `@connectrpc/connect-node: npm:@gchigoo/connect-node@1.7.1`，让 Cursor SDK 的 semver 依赖去重到安全包。

方案深度核对：安全分发是核心正确性路径，不能使用只在开发根生效的 override、可绕过的 install script 或平台不完整 bundle；维护小型 permissive fork 是满足跨平台与消费端安全的完整方案。

## Changes This Iteration

- 新增 `packages/connect-node/`：53 个 upstream dist 文件、patched package manifest、README、Apache-2.0 LICENSE 与 NOTICE。
- 新增 `scripts/test-connect-node-fork.mjs`：校验 upstream 字节一致性、pack budget、独立安装、Undici 版本、ESM/CJS import 和生产 audit。
- 更新 `scripts/test-packed.mjs`：从真实消费端安装根检查 Undici 树与 production audit，并保证失败时清理 tarball。
- 更新 `scripts/verify-manifest.mjs` 和根 `prepublishOnly`，把 fork metadata 与验证纳入 gate。
- 更新 goal 边界：允许后续安全版本，但不要求消费者 override、不使用 install guard、不重新分发 Cursor SDK。

- 在增强 packed gate 前执行的完整 `prepublishOnly`：64 tests、typecheck、boundaries、manifest、Pi load、fork test 均通过；旧 packed gate 和根 audit 通过，但已确认不能代表消费端安全。

## Problems Encountered

- 发布包携带 `npm-shrinkwrap.json` 的隔离实验仍让消费者安装 `undici@5.29.0`，已排除。
- 只 bundle Connect Node 时，npm hoist 会让 Cursor SDK 在消费根另装官方 Connect Node，仍不安全，已排除。
- npm alias 去重隔离实验确认：目标包版本满足 `^1.6.1` 时 Cursor SDK 可复用直接依赖。真正使用 `@gchigoo/connect-node` 的 registry 验证必须在该包发布后完成。
