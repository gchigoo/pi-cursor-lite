# Iteration 004

## Current Understanding

GitHub 与 npm 发布成功，Pi 也已从本地路径切到 npm 版本并可加载模型；但消费者安装不会继承 `pi-cursor-lite` 自身的 npm overrides，因此实际安装树重新出现已知漏洞。

## Implementation Approach

先验证 registry 和 Pi 安装结果，再对 Pi npm 安装根执行 `npm ls` 与生产 audit；发现风险后立即停止，不接受风险、不发布新版本、不卸载当前版本。

## Changes This Iteration

- 创建并推送 public GitHub：`https://github.com/gchigoo/pi-cursor-lite`。
- 发布 npm：`pi-cursor-lite@0.1.0`，`latest=0.1.0`。
- Pi 已移除本地路径 source，并安装 `npm:pi-cursor-lite@0.1.0`。

## Verification Evidence

- GitHub public、remote main 与 commit `d8a861f0e1588a8c33ebdbdaf014648ab10e60fa` 一致。
- npm registry 元数据、作者 Gchigoo、MIT、repository 与 latest tag 正确。
- `pi --list-models cursor-lite` 显示 `cursor-lite/auto`。
- Pi npm root 的 `npm ls undici`：`@cursor/sdk → @connectrpc/connect-node@1.7.0 → undici@5.29.0`。
- Pi npm root 的生产 audit：1 high、3 moderate，均由该链路引入。
- 临时 bundle 试验可把 audit 降为 0，但包增至 8,376,169 bytes / 38,004,107 unpacked / 1,822 files，只包含 Windows optional SDK，且 undici semver 被标为 invalid，不可作为跨平台正式方案。

## Problems Encountered

npm 的 `overrides` 只由 install root 使用，不从已发布 dependency 传播；开发仓库 audit 绿色不能证明 registry 消费者安装树安全。

## Next Attempt
